# 模型调用观察台 0.1.2

基于 ALIPRO 1.9.18 工作区继续开发，已加入 Windows 客户端。先读 [调用点位矩阵](../../docs/模型调用点位矩阵.md)。

## 推荐：在客户端内实验

开发机双击项目根目录 `start-model-experiment.cmd`，或执行 `npm run experiment:models`。自动读取此前下载的《血裔迷途》单书导出，创建新的本地实验数据库，启动当前后端与桌面窗口。进入“模型观察台”，点击“打开观察窗口”；也可在客户端菜单“视图”打开，快捷键 `Ctrl+Shift+M`。无需另开浏览器或手动启动观察台。

实验数据库、模板、日志、采集记录、客户端账号缓存分开保存在 `%LOCALAPPDATA%/ALIPRO/model-experiments/run-*`。每次启动建立新副本，退出后保留结果；原始本地数据库和云端作品不修改。复制数据使用本地匿名所有权；导出中章节细纲的12个空章节引用按未关联处理为NULL，记录在experiment.json中。副本来源为2026-09-27下载的快照，不代表云端今天的最新内容。

本实验入口需要项目已有 Node.js、backend/apps/windows依赖和当前前端构建。模型密钥使用 `backend/.env` 的配置，密钥不随普通EXE打包。生成正常消耗模型额度。实验后端和观察台均只监听本机回环地址；关闭实验客户端会停止实验后端。不要在实验窗口登录云端账号。

普通新版 Portable/Setup 也自带观察台窗口，侧栏“系统 → 模型观察台”进入。普通客户端仍连接云端；本机观察窗口会明确提示云端采集尚未接通。云端请求要看到完整模型输入，仍需另行部署后端采集与授权读取链路。本次没有部署云端。

### 第一轮实验

1. 先生成一个书名/角色名，确认出现真实输入、输出和采集心跳。
2. 在《血裔迷途》副本中挑一章，固定模型和参数生成A，只改变一条要求生成B。
3. 在B的“前后对比”选A，检查新增段落、重复长行与字符增长。关注同次操作中的初稿、审校、修稿，不能把不同阶段当作同点位比较。
4. 用第11章检查上一章已经获得的线索有没有重讲；对照人物状态、支线节点和锁魂印设定。需要生成前先确认细纲确实包含要推进的目标。
5. 填“我的判断”，复制诊断包或导出完整JSON发给助手。第一轮只做一章，避免批量成本和难以定位的多个变量。

## 启动

在项目根目录双击 `start-model-monitor.cmd`，或运行 `npm run monitor:models`。需要本机 Node.js，不需要新增 npm 依赖。默认只监听 `127.0.0.1:4318`；启动时显示带本次访问令牌的完整链接，双击启动会自动打开浏览器。关闭窗口不影响作品生成。

监控的是**启用了此采集代码的后端进程**。当前代码在非 production 环境默认采集；后端进程需要重新启动才能加载新代码。设置 `ALIPRO_AI_MONITOR=1` 显式开启，设置为 `0` 关闭。观察台出现采集心跳后，在连接该后端的创作界面操作即可。

1.9.0 Portable 默认连云端；在本地打开观察台不能直接看到尚未接入采集的云端请求。云端使用需要另行部署采集代码、显式开启采集，并通过授权的私有连接将采集目录同步到本机，或把只监听回环地址的观察台通过 SSH 转发访问。本次未部署云端；实验客户端使用本地地址，普通客户端默认地址保持云端。不要把本地无记录当作云端没有调用。

环境变量：

| 配置 | 用途 |
|---|---|
| ALIPRO_AI_MONITOR | `1`开启 / `0`关闭；生产默认关闭 |
| ALIPRO_AI_MONITOR_DIR | 后端和观察台必须设置为同一目录 |
| ALIPRO_MONITOR_PORT | 观察台端口，默认4318 |

默认Windows目录为 `%LOCALAPPDATA%/ALIPRO/model-monitor`；其他系统为 `~/.local/share/ALIPRO/model-monitor`。原始文本不放入Git。按请求保存JSON，暂不自动删除历史记录，请按需归档。

## 使用顺序

1. **点位矩阵**：查看37个文本模型调用点及1个TTS适配点，理解每步输入、输出与重试条件。
2. **操作列表**：一次HTTP操作中的生成、审校、修稿和网络重试放在一组。不同HTTP请求不会假装是同一条链，可按作品、章节或点位搜索。列表默认150条，可加载到1000条；统计注明范围。
3. **输入/输出**：保留完整发送消息和原始顺序；非流式完成后显示输出，流式约每秒刷新。可暂停显示、继续后台采集。标题分段和重复长行只用于定位，不会修改输入。
4. **前后对比**：选择同一点位的另一次调用，查看字符量增减、输入指纹和新增/减少文本行。按行及出现次数比较，行重排不会当作新增，参数变化会单独提示。过滤器可能隐藏旧记录，可先清除过滤。
5. **交流修正**：填“我的判断”，复制诊断包，或导出完整JSON。包含阶段、模型、源码指纹、参数、输入输出与备注，可直接交给助手定位。截图模式隐藏侧栏并展开内容，也可浏览器打印保存。

## 数据语义

- 记录最终发送给提供商的请求体，而不是预览草稿。system/user/assistant和模型参数保留。请求头、API密钥、登录令牌不采集。
- 文本HTTP请求按每次网络尝试记录，logicalCallId关联同一次逻辑调用，traceId关联同一HTTP操作；提供商降级也保留两次记录。
- 流式记录原始SSE解码文本及收到的正文增量，错误/取消时保留部分输出；进程意外退出的记录在观察台标记中断。多进程同时采集使用唯一请求ID。
- “已完成”只表示这次模型传输和基础响应校验完成，不代表生成内容通过业务审查、JSON业务结构解析成功、已经入库或最终被采用。自动修稿的采用结果仍须结合原有审校反馈判断。
- 输入字符与提供商token分开显示；未返回token时显示“未返回”，不把字符数冒充token数。
- 源码版本仍显示1.9.18，实际点位文件和适配器指纹用于区分未发布修改。观察器不自动裁剪、去重或追加提示词。
- TTS记录实际Node→Python分段文本、音色等参数和返回状态；不采集音频二进制，也不捕获Python内部网络包、库内部重试或隐藏提示。
- 采集写入失败会告警并放行原生成。需要关注心跳、采集错误提示和磁盘空间；不要将无记录解释为模型无请求。
