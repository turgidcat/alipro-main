唯一开发基线是当前仓库的 **1.9.18 源码工作区**：Windows 桌面外壳 `apps/windows`、共用界面 `apps/web`、配套后端 `backend`，并保留其中尚未单独编号的本地改动，包括上一章上下文进入自动修稿的补丁。

1.9.18 是源码版本标记，不是不可变快照；实施前应记录当时源码指纹和相关未提交改动。版本脚本此前预估下一次构建为1.9.19，这只是自动构建编号，不影响以当前1.9.18工作区为本方案起点。

1.9.0会议反馈和云端导出的作品数据用于提供复现样例。每项旧问题必须在当前源码链路确认是否仍存在，再决定修复；当前已有能力直接复用，不因为旧客户端缺少入口或云端尚未部署而重复开发。旧包和云端版本核对移到文末，作为交付背景。

## 2. 分版本实施顺序

以下是从当前1.9.18工作区向前演进的**计划版本**，保留此前使用的1.10.0、1.11.0、1.12.0编号。完成范围收口后再通过现有版本机制准备正式构建；当前不提前修改包版本或发布记录。

### 1.10.0：修补现有生成链路

重点：先确认当前版本还会出现哪些旧问题，再修复。

1. 使用已下载的《血裔迷途》数据建立本地复现样例，追踪支线节点和角色是否进入当前版本细纲及正文上下文。
2. 定位“节点遗漏、未来节点提前执行、关联角色全员出场、章节目标反复复用”的具体原因，仅修复确认存在的缺陷。
3. 验收当前已有的上一章上下文修稿补丁，重点用第10–11章重复揭示案例。
4. 核对手改正文后摘要、人物状态和事实台账是否同步；如有陈旧信息继续参与生成，补齐更新或失效处理。
5. 基于明确设定核对角色受伤后反复爆发、反派动机跳变等问题；区分作品资料缺失和代码没有正确读取约束。

完成条件：本地1.9.18基线与修改后的样例结果有可对照记录；本章应读的节点、角色和手改事实确实进入输入，已确认的缺陷有针对性验证。既有13项质量策略测试通过仅作检查记录，不能替代样例效果验收。

### 1.11.0：补齐会议明确要求的创作功能

1. 新增卷时支持AI生成该卷名称、阶段目标和核心冲突，允许补充想法和手动修改。
2. 年龄、性别贯通角色生成、保存、编辑、卡片标签与正文上下文。
3. 基于已有剧情线角色关联和本章角色字段，补齐细纲完成后的角色确认交互，支持增删与职责调整。
4. 改善爽点、口语化等生成参数入口的可发现性。
5. 移除人工盲标流程，保留自动审校与连续性反馈。

完成条件：在基于当前源码构建的桌面端完成“新增卷 → 剧情线/角色 → 细纲 → 确认人物 → 正文 → 反馈”操作验收；输入可保存，重新打开保持一致，人工调整真实影响后续生成。

### 1.12.0：连续生成与作品阶段验收

1. 创作侧确认第一卷覆盖范围：导出数据中第一卷预计15章，而关联剧情线延伸到50–52章；确定意图后再统一规划，不把数据冲突直接当作新版代码缺陷。
2. 补明确的锁魂印规则、反派动机、秘境出入口、角色功法/伤势/代价/恢复条件，复用现有资料与状态能力。
3. 确定已有1–11章的修订起点，复核后分批推进到30–40章，逐章记录角色、支线、状态和设定问题。
4. 修复连续运行中发现的剩余缺陷，核对节奏不过早跨阶段、信息不重复揭示、人物状态不重置。

完成条件：30–40章有实际验收记录，已确认矛盾被处理，人工改动被后文承接；不能用一次生成成功代替多章验收。

100章是后续作品里程碑，达到阶段稳定后再推进并人工审稿、准备发布。新书、剧本和漫剧暂不列入上述版本。
