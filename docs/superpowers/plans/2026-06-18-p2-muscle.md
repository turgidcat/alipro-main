# P2 肌肉阶段 Implementation Plan

**Goal:** 在不推翻 `P1` 双栏骨架的前提下,补齐真实交互、继续拆分 `App.jsx`,把创作台从“能用骨架”推进到“顺手工具”。

**Current Baseline:**

- `P0` 已完成主体: 路由、Tailwind、`lib/`、`useWorkbench`、基础组件拆分都已落地
- `P1` 已完成主体: `GlobalBar`、`ChapterConfigPanel`、`ContentWorkspace`、`ContextDrawer`、4 个 drawer、双栏布局都已落地
- 当前主要缺口:
  - `App.jsx` 仍约 `1347` 行,大量 modal / 校改流程仍塞在主文件
  - `ChapterList.jsx` 还是占位三态
  - 生成参数仍裸露在主区,没有进次级入口
  - 快捷键、抽屉记忆、未保存提示都还没做
  - `styleTheme.js` / 样式管理页仍是旧体系,不属于 P2,但要避免继续加重技术债

**Tech Stack:** React 18、react-router-dom 6、现有手写 CSS、已有 `workbenchApi` / `useWorkbench`

**Spec:** `docs/superpowers/specs/2026-06-18-frontend-overhaul-design.md` 第六节

**P2 核心约束:**

- 不推翻 `P1` 双栏 + 抽屉的信息架构
- 不抢跑 `P3` 视觉系统,只做必要的结构与交互收口
- 每个任务结束后页面都应继续可用

## Task 1: 把章节列表三态从占位逻辑改成真实状态

**Why:** 现在的 `ChapterList.jsx` 只是“当前章之前默认有内容”的假算法,它能演示入口,但不能代表真实数据状态。

**Files:**

- Modify: `frontend-react/src/components/workbench/ChapterList.jsx`
- Modify: `frontend-react/src/App.jsx`

**Implementation idea:**

1. 在 `App.jsx` 基于已有 `planningState`、`chapterContext`、当前书章节记录,整理一个 `chapterListItems`
2. 每项至少包含:
   - `chapterNumber`
   - `chapterName`
   - `status: 'has-content' | 'plan-only' | 'empty'`
3. 把 `ChapterList` 改为接收 `items` 数组,不在组件内部猜状态

**Status rules(保守版):**

- 有正文: 对应章节记录存在且正文非空
- 仅有计划: 没正文,但 `chapter_plans` 已有 `outline_text` / `chapter_structure` / `summary` 等任一有效字段
- 空章: 两者都没有

**Acceptance:**

- 章节列表能真实显示三态
- 当前章高亮保持不变
- 点击任一项跳章正常

## Task 2: 抽出 GenerationBanner,把生成前状态摘要从主文件中独立

**Why:** 生成前的“必填信息 / 建议补充 / 风险提示”现在散在 `ContentWorkspace` 和 `App.jsx` 的派生数据里,阅读成本高。

**Files:**

- Create: `frontend-react/src/components/workbench/GenerationBanner.jsx`
- Modify: `frontend-react/src/components/workbench/ContentWorkspace.jsx`
- Modify: `frontend-react/src/App.jsx`

**Implementation idea:**

1. 新建 `GenerationBanner.jsx`,接收:
   - `generationReadiness`
   - `generationRequiredItems`
   - `generationRecommendedItems`
   - `generationRiskReview`
   - `generationRiskConfirmed`
   - `onGenerationRiskConfirm`
2. `ContentWorkspace` 只保留“生成动作”和“结果展示”,把状态摘要组件化
3. 保持现有业务逻辑不变,只搬 JSX 和 props

**Acceptance:**

- 生成前状态区域仍能完整显示
- 高风险确认 checkbox 行为不变
- `ContentWorkspace.jsx` 明显变短

## Task 3: 抽出 RevisionEditor,把校改弹窗主体从 App.jsx 移走

**Why:** 现在 `App.jsx` 最大的体积来源之一就是校改 modal。先把最重的一坨搬出去,`App.jsx` 才有机会继续瘦身。

**Files:**

- Create: `frontend-react/src/components/workbench/RevisionEditor.jsx`
- Modify: `frontend-react/src/App.jsx`

**Implementation idea:**

1. 保留 `Modal` 容器在 `App.jsx` 或直接一起移入 `RevisionEditor`
2. 把以下内容整体搬到 `RevisionEditor.jsx`:
   - 左右对照阅读区
   - 建议列表
   - 聚焦跳转
   - 应用建议按钮
   - 保存 / 润色动作区
3. 组件只通过 props 工作,不直接调 API

**Minimum props:**

- 原文 / 草稿 / 建议列表 / 当前 focus
- 段落 ref 注册函数
- 建议 ref 注册函数
- 各类保存 / 润色 / 应用建议 handler
- notice / error / loading 状态

**Acceptance:**

- 打开校改弹窗行为不变
- 建议跳转、应用、保存、润色都不回归
- `App.jsx` 删除大段校改 JSX

## Task 4: 把生成参数收进次级入口,不再裸露在主区

**Why:** 按 spec,字数和更低频的生成调节属于 `L2`,继续裸露在主区只会把界面越堆越满。

**Files:**

- Create: `frontend-react/src/components/workbench/GenerationSettingsPopover.jsx`
- Modify: `frontend-react/src/components/workbench/ContentWorkspace.jsx`
- Modify: `frontend-react/src/workbench-layout.css`

**Implementation idea:**

1. 在“查看生成摘要 / 生成章节”旁边增加一个 `⚙ 参数` 次级入口
2. 先只把现有 `word_count` 移进去,不强行加 temperature 等新字段
3. 弹层里保留:
   - 目标字数 input
   - 一句说明文字
4. 这样能先完成“L2 收口”的结构动作,而不会引入新后端参数

**Acceptance:**

- 主区不再直接显示字数 input
- `⚙ 参数` 内仍可修改目标字数
- 生成行为保持一致

## Task 5: 补齐 3 个关键交互

**Why:** 这三项是用户能明显感知到的“从骨架变顺手”的分水岭。

### 5.1 快捷键

**Files:**

- Modify: `frontend-react/src/hooks/useWorkbench.js`
- Modify: `frontend-react/src/App.jsx`

**Rules:**

- `Ctrl+Enter`: 触发生成
- `Esc`: 关闭抽屉 / 关闭当前顶层弹窗
- `[` / `]`: 前后翻章(输入框聚焦时不拦截)

### 5.2 抽屉记忆

**Files:**

- Modify: `frontend-react/src/hooks/useWorkbench.js`

**Rules:**

- 以 `bookId + chapterNumber` 为 key 保存最近一次打开的 drawer
- 重新进入同一本书同一章时恢复
- 若没有记录,默认不自动打开

### 5.3 未保存提示

**Files:**

- Modify: `frontend-react/src/hooks/useWorkbench.js`
- Modify: `frontend-react/src/App.jsx`

**Rules:**

- 只跟踪左栏高频配置的脏状态
- 用户翻章或点击生成前,若存在未保存修改,弹确认
- 不做浏览器 `beforeunload` 全局拦截,先只做应用内拦截

**Acceptance:**

- 快捷键在创作台可用
- 抽屉状态能记忆
- 修改左栏后直接翻章/生成会被提醒
