# 字数控制统一规范

> 本规范以 `shared/word-count-policy.json` 为唯一配置源。前端显示、后端生成、修订、Judge、Harness 和验收脚本都必须引用同一套规则；本文档只解释规则，不另行维护一份数字。

## 1. 统一口径

- 计量单位是“有效字”（`effective_characters`），不是模型 token，也不是数据库字符串长度。
- 先去掉乱码替代符（`�` / U+FFFD）、控制字符并清理首尾空白；再去掉空白、Unicode 标点和 Unicode 符号；最后按 Unicode code point 计数。
- JavaScript 必须使用 `Array.from()` 计数，不能使用 `string.length`。前端 `countPlatformEffectiveWords()` 与后端 `countPlatformEffectiveWords()` 必须保持同样行为。
- `word_count` 和 `word_count_audit.actual` 表示同一口径的有效字数。模型返回的 token 数只能用于预算和成本记录，不能当作字数验收结果。

## 2. 目标、范围与通过条件

- 默认目标：**3000 有效字**。
- 用户可设置范围：**500–10000 有效字**；前端输入和后端入口都要限幅。
- 通过窗口：目标值的 **±15%（含边界）**。
- 下限：`floor(target × 0.85)`；上限：`ceil(target × 1.15)`。
- 例如目标 3000 时，实际 2550–3450（含 2550 和 3450）才算通过。
- 目标或正文为空时，字数状态为 `not_applicable`，不因字数阻断其他审计；有正文后必须按上述窗口判定。
- 模板可以提供题材专用目标值，但不能改变计数口径、范围或 ±15% 窗口。

## 3. 生成与修订规则

- 正文 Prompt、结构化生成、确定性 Judge、质量审计和批量验收均从共享策略读取边界，禁止各自写 `0.85`、`1.15` 或另一套默认值。
- 字数修订最多 3 次。
- 修订 token 预算统一限制在 **350–6500**；扩写倍率 1.25，压缩倍率 0.90。
- 质量修复 token 预算统一限制在 **1400–6500**。
- 软目标为目标值的 95%，用于给模型留出修订余量；软目标不是最终通过条件。
- Harness 命令未显式传 `--target-word-count` 时使用默认目标 3000；为了低成本测试而使用其他字数时，必须显式传参并在报告中记录。

## 4. 实现位置与验收

- 唯一配置：`shared/word-count-policy.json`
- 后端适配：`backend/services/word-count-policy.js`
- 前端适配：`frontend-react/src/lib/wordCountPolicy.js`、`frontend-react/src/lib/textMetrics.js`
- 判定与修订：`backend/routes/ai.js`、`backend/harness/deterministic-judge.js`
- Harness 默认值：`backend/harness/run-isolated-generation.js`、`backend/harness/prepare-soak-baseline.js`

修改任何字数规则时，只改共享 JSON，并同步更新本文件的解释；禁止在业务代码中重新定义一套数字。

建议验收：

```text
cd backend && npm run test:harness -- --test-name-pattern=字数
cd frontend-react && npm run verify:frontend-contracts
cd frontend-react && npm run build
```
