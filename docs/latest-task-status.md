# 最新全量任务清单

> 刷新时间：2026-06-18
> 适用项目：`alipro-main`
> 说明：本清单基于最近几天的真实开发记录、页面状态、接口验收结果和既有改造文档整理，只校准任务进度与当前状态，不主动删除原有改造方向。

## 一、校准原则

- 保留原有大方向：创作主链、数据底座、React 迁移、资料库、剧情线闭环、反馈闭环。
- 不把“已做过一点”误判成“已完成”。
- 不把“已经设计过”误判成“已经落地”。
- 把最近真实新增的问题也纳入清单，但只作为补充项，不替换旧条目。

## 二、已完成

### 1. 创作主链 React 接管

- React 工作台已经成为主前端入口。
- 首页创作台主体已经迁入 React，包括：
  - 全书规划区
  - 单章设置区
  - 正文生成区
- 当前主入口已经是 `frontend-react`，旧静态前端转为兼容入口保留。

### 2. 章节规划主对象落地

- `chapter_plans` 已经成为章节规划主表。
- 后端已经支持并实际读写这些核心字段：
  - `chapter_name`
  - `summary`
  - `chapter_mission`
  - `emotion_target`
  - `outline_text`
  - `scene_outline`
  - `character_notes`
  - `appearing_roles`
  - `previous_hook`
  - `ending_hook`
  - `main_storyline_id`
  - `target_storylines`
  - `structured_content`
- 前端章节规划读取、保存、回填已经接通。
- “章节大纲”已经升级为更结构化的章节任务表单，不再只是自由文本备注。

### 3. 正文生成基础链路跑通

- 正文生成已经不再只靠旧页面临时拼数据。
- 生成链路已经能够读取：
  - 当前书籍信息
  - 全书 / 章节上下文
  - 章节任务表
  - 角色设定摘要
- `POST /api/generate` 已经真实跑通并能返回正文。
- 生成后的正文可以写回章节记录。

### 4. 生成后基础反馈闭环已接通

- 生成正文后，系统已经能够形成基础版本章反馈。
- 下一章已经可以读取上一章的部分承接信息。
- 这意味着“生成不是完全失忆的单次调用”这一层已经迈过去了。
- 现已补充真实前端回归：
  - `/workbench` 上重新生成后，正文、反馈和章节计划会同步刷新
  - 打开校改弹窗直接保存后，反馈也会再次刷新并写回

### 5. 校改能力恢复可用

- `POST /api/polish` 已经过真实接口验收。
- 校改 prompt 的关键乱码问题已经修掉。
- 现在校改接口能返回正常润色正文，不再把输入正文识别成问号占位符。

### 6. 资料库 React 主体改造完成

- 资料库页面已经迁入 React。
- 目前已经具备并验收过的内容包括：
  - 书籍列表
  - 搜索和筛选
  - 批量操作
  - 新建 / 编辑弹窗
  - 书籍详情页
- 资料库详情已经能读到真实的：
  - 书籍信息
  - 全书大纲
  - 角色档案
  - 章节记录

### 7. 演示环境与基础工程状态可用

- 前后端都可以正常启动。
- React 前端 `vite` 工作正常。
- `frontend-react` 构建已通过。
- 已补过一轮演示书籍数据，书库已经不是单书空壳状态。
- 《破雾修真录》当前 1-8 章任务表已连续挂回血月旧案主线。
- 但这不等于 1-8 章都已经是完整长正文样板：前段章节仍保留短正文种子，后段章节才更接近真实生成样本。

## 三、进行中

### 0. 前端整体改造进入新阶段

- `zcode` 分支上已完成前端整体改造的 `P0` 与 `P1` 主体施工:
  - 路由切换到 `react-router-dom`
  - `App.jsx` 已拆出 `lib/`、`hooks/useWorkbench.js`、`components/workbench/`
  - 创作台已改为“顶部全局条 + 左右双栏 + 低频抽屉”
- 但这不等于前端改造已经收口:
  - `App.jsx` 仍有约 `1347` 行
  - 章节列表三态还是占位算法
  - `P2` 交互补齐和 `P3` 视觉系统尚未实施
- 当前更准确的表述应是:
  - **工程地基和信息架构已搭好**
  - **交互细化与设计语言仍在后续阶段**

### 1. 第一阶段“章节规划收口”仍在收尾

- 结构化章节任务表已经上线。
- 但还不是所有演示书、所有章节都补齐成了完整任务数据。
- 当前更像是：
  - 主链模型已经成型
  - 主要演示样本已经补到可判断状态
  - 页面文案和台账口径还在继续收口

### 2. 创作主链“从任务表到正文”的质量收口

- 主链已经能从任务表生成正文。
- 但仍存在生成质量约束没完全收住的问题，尤其是：
  - 目标字数控制需要继续实测校准
  - 个别 prompt 仍需继续做历史残留清理
- 当前状态应定义为“可用，但未精修完成”。

### 3. 反馈闭环处于基础可用状态

- 反馈已经能写回并参与下一章承接。
- 但它还没有成为一个独立、稳定、可审计的正式层。
- 当前反馈更偏“挂在章节规划里的结构化结果”，还不是完整反馈系统。

### 4. 剧情线接入处于半联动状态

- 前端已经能保存 `main_storyline_id` 和 `target_storylines`。
- 章节规划层已经为剧情线留出接入口。
- 《破雾修真录》1-8 章任务表当前都已挂到同一条主线。
- 但剧情线还没有真正形成：
  - 自动推进
  - 自动回写状态
  - 自动影响下一章目标

### 5. 资料库 React 改造仍在收口

- 主体页面已经完成。
- 但“资料库作为长期规划与资产管理中心”的深层定位还没彻底做完。
- 当前更偏“可用版本”，不是“最终收口版”。

### 6. 后端历史乱码清理仍在进行

- 已修：
  - `backend/services/deepseek.js`
  - `backend/routes/ai.js` 主链核心 prompt
  - `backend/server.js` 启动与错误文案
- 未完全修：
  - 其他历史后端文件中的注释、日志和非主链文案

  - 根据剧情线状态生成下一章建议

- `chapter_feedback` 还没有独立表结构。
- 反馈还没有形成正式的可查询、可审核、可比对层。
- “反馈 -> 剧情线状态”已有基础写回，“剧情线状态 -> 下一章目标”还未完成。

### 4. 正文字数控制

- 目标 3000 字时，虽然已经通过后端预算收紧把实测结果压到约 3106 字，但这还属于阶段性校准结果。
- 还需要再用不同章节、不同题材做一轮稳定性验证，确认不是单样本偶然成功。

### 5. 批量生成重新验收

- 已按新主链在 2026-06-14 重新复验一轮：

  - 本轮字数浮动均在 10% 内。
- 剩余问题不是生成接口不可用，而是批量验收范围、演示书样本区间和页面说明口径还没有完全收成一套。

### 6. 旧静态前端下线

- 旧静态入口仍然保留。
- 目前它是兼容层，不是废弃层。
- 真正下线旧入口的时机还没到。

### 7. 辅助页面与非主链区域深修

  - 章节任务表
