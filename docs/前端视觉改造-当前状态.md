## 三、尚未完成的改造（本次对话讨论的所有设计决策）

### 3.1 整体设计方向：Amber Workbench

**风格定位**：编辑器风格（VS Code / Linear），不是卡片式 dashboard。

**色板**：
- 亮色模式：canvas `#fafaf9`（stone-50），surface `#ffffff`，brand `#ea580c`（orange-600），ink `#1c1917`（stone-900）
- 暗色模式：canvas `#0d1117`，brand `#f97316`（orange-500）
- 所有灰色使用 stone 暖灰色系，禁止 cool gray

**字体三层规则**：
- 衬线（serif）：正文/创作内容
- 无衬线（sans）：UI 标签/按钮/中文元信息
- 等宽（mono）：仅用于纯英文/数字/符号的元信息（如字数统计）

**字号四级体系**：
- meta 12px：仅英文等宽（如字数 "2,341 字"）
- caption 13px：中文最小字号（标签、次要信息）
- body 15px：衬线内容最小字号（大纲、角色描述）
- prose 17px：主要阅读字号（正文预览）

**对比度规则**：
- ink-3（`#a8a29e`，对比度 ~2.5:1）仅用于 ≥14px 非关键文字
- <14px 必须使用 ink-2（`#57534e`，对比度 ~5.2:1）

### 3.2 布局范式转换：从卡片式到分区式

**现状问题**：内容密集时，卡片（PanelCard）层层嵌套产生 N×N 边框线，视觉噪音大。

**目标**：分区式布局（类似 Linear / GitHub Settings）：
- 去掉卡片容器，内容直接铺在 canvas 背景上
- 用 `border-left` 彩色规则 + 间距 + 分隔线来分组
- 每个区块是独立的 section，不是嵌套的 card
- 生成状态用薄 banner 而非整块卡片
- 正文预览直接在 canvas 上，不需要圆角容器

### 3.3 三栏可折叠工作区（VS Code / Scrivener 风格）

**目标交互**：
- 左栏：章节导航 + 配置（可折叠）
- 中栏：编辑器/预览区（主工作区）
- 右栏：检查器/反馈（可折叠）
- 三栏各自独立折叠，通过拖拽分割线调整宽度

**技术选型**：shadcn/ui 模式（源码复制到项目中，不是 npm 包）。需要的组件：
- `ResizablePanel` — 三栏拖拽分割
- `Separator` — 分隔线
- `Sidebar` — 侧边栏
- `Button`、`Tabs` — 基础控件

### 3.4 StyleManager 精简改造

**现状**：
- `StyleManagerPage.jsx`：1573 行，独立页面 `/style-manager`，在主导航中有一个入口
- `styleTheme.js`：940 行，4 个页面主题 × 5 个品牌色 × 3 个导航风格 × 3 个按钮风格 = 180 种组合
- 实际效果：大部分组合视觉差异极小（圆角值重复、色相被 clamp 在 ±18%）

**目标改造**：
- **保留能力**：前端运行时可以切换主题
- **替换实现**：
  - 独立页面 → GlobalBar 上的弹出面板（popover）
  - `styleTheme.js` 从 940 行精简到 ~60 行
  - 只保留 3 个控制维度：明/暗模式 + 橙色强度（3 档）+ 正文字体（衬线/无衬线）
- **Token 系统迁移**：旧的 `--brand` / `--line` / `--panel` → 新的 Tailwind 语义 token（`--background` / `--foreground` / `--primary` / `--border`）

### 3.5 Tailwind 配置

**现状**：
```js
// tailwind.config.js — 10 行
theme: {
  extend: {}  // 空的，注释说"P0 阶段不扩展"
}
```

**目标**：填入完整的 amber 语义 token，使 shadcn 组件和自定义样式都能响应主题切换。
