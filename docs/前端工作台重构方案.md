# Alipro 前端工作台重构方案

> 文档状态：计划中，尚未执行任何 Phase  
> 适用分支：`p4-workbench-refactor`  
> 范围：仅重构 `frontend-react/` 前端工作台；不修改后端、数据库或 AI 生成接口

## 1. 项目背景

Alipro 是 AI 小说生成工具。当前前端位于 `frontend-react/`，技术栈为 React 18、Vite、Tailwind CSS 4 和 `react-router-dom` 6。

本次重构只调整前端工作台的视觉系统、主题入口和页面布局。现有章节计划、剧情线、角色、生成、保存、反馈和校改逻辑继续复用；后端接口、数据库结构、AI 生成接口及其请求参数均不在本次范围内。

当前实际入口与关系如下：

- `frontend-react/src/main.jsx`：加载主题并引入 `index.css`、`styles.css`。
- `frontend-react/src/AppLayout.jsx`：全局顶栏和主导航，目前含“样式管理”入口。
- `frontend-react/src/router.jsx`：注册 `/workbench` 与 `/style-manager` 等路由。
- `frontend-react/src/components/workbench/WorkbenchStage.jsx`：当前工作台主体，实际为左右两栏。
- `frontend-react/src/components/workbench/ChapterConfigPanel.jsx`：章节计划、剧情线、角色等配置。
- `frontend-react/src/components/workbench/ContentWorkspace.jsx`：生成前检查、生成操作与生成结果。

## 2. 当前问题

### 2.1 工作台是卡片堆叠式布局

`WorkbenchStage.jsx` 当前使用两栏 Grid：左栏放 `ChapterConfigPanel`，右栏放 `ContentWorkspace`。两侧组件继续通过 `PanelCard.jsx` 组织内容，而 `ChapterConfigPanel.jsx` 内又使用 `insetSurfaceClass`，`ContentWorkspace.jsx` 内还有独立圆角、边框和渐变容器。

结果是“页面 → PanelCard → inset surface/结果容器”的盒子套盒子结构，边框、圆角、渐变和间距重复，正文编辑区没有成为视觉主体。

### 2.2 主题引擎过重且假可调

真实文件是 `frontend-react/src/styleTheme.js`，不是 `src/theme/styleTheme.js`。当前包含 `THEME_RECIPES`、`PAGE_THEME_TOKENS`、`BRAND_THEME_TOKENS`、`NAV_THEME_TOKENS`、旧主题迁移和大量派生计算；`paper / cool / deep / signal` 等预设参数很多，但用户感知差异有限。

主题功能需要收敛为三个真实可见、能稳定生效的运行时控制：明暗、暖橙深浅、正文字体。

### 2.3 StyleManager 页面权重过高

`StyleManagerPage.jsx` 目前拥有独立页面；`router.jsx` 注册 `/style-manager`，`AppLayout.jsx` 将它放在主导航，`frontend-react/package.json` 还有 `verify:style-manager` 脚本。主题只是工作环境偏好，不应与资料库、创作台等业务页面同级。

### 2.4 样式入口与组件基础设施不足

Tailwind 唯一入口为 `frontend-react/src/index.css`，当前直接加载字体、`tailwindcss`、配置和源码扫描。仓库当前没有 `frontend-react/src/components/ui/`，也没有通用的 Popover、Tabs、Resizable、Separator 或 Sidebar 基础组件。

## 3. 重构目标

1. 将工作台从卡片堆叠改为编辑器式分区布局，正文成为中栏主视觉。
2. 建立 `WorkbenchNavigator + WorkbenchMain + WorkbenchInspector` 三栏结构，左右栏可折叠、三栏可拖拽，正文可一键全屏。
3. 将视觉 DNA 固定为“编辑器派 + 暖橙”，底色只使用 stone 暖灰与 orange 暖橙体系。
4. 用语义 token 代替页面直接依赖旧主题变量，并在迁移期保留兼容映射。
5. 将 StyleManager 降级为顶栏 `ThemePopover`，只保留三个真正生效的控制项。
6. 采用 shadcn/ui 源码模式补齐小型基础组件，不引入大型 UI 框架。
7. 只改变展示与交互外壳，不改变字段含义、状态来源、保存顺序、接口调用和数据落库边界。

## 4. 视觉规范

### 4.1 视觉 DNA

- 参考范式：VS Code、Linear、Scrivener、novelWriter 的编辑器工作台。
- 默认亮色背景：`#fafaf9`。
- 亮色主强调色：`#ea580c`。
- 暗色主强调色：`#f97316`。
- 色彩范围：stone 暖灰 + orange 暖橙。
- 禁止冷蓝或冷灰成为主视觉；禁止继续用统计卡片表达创作工作流。

### 4.2 分区表达

- 一级结构靠栏位宽度、背景层级和细分隔线区分。
- 二级内容使用左边线、区块标题和垂直间距，不再默认套圆角卡片。
- 正文直接铺在暖白背景上，不加装饰性渐变或厚重阴影。
- 元信息使用 `SECTION 01`、`STORYLINE`、`CH.03` 等英文/数字代号，不使用中文胶囊徽章。
- 圆角只保留在按钮、输入框、Popover 等确实需要点击边界的控件上。

## 5. 字体与字号规范

### 5.1 字体角色

| 角色 | 字体栈 | 使用范围 |
| --- | --- | --- |
| serif | `"Noto Serif SC", "Source Han Serif SC", "Songti SC", Georgia, serif` | 小说正文、创作描述、大段文本 |
| sans | `Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif` | UI 标签、按钮、输入框、中文元信息 |
| mono | `"JetBrains Mono", "SF Mono", Consolas, monospace` | 纯英文、数字、符号元信息 |

禁止对中文使用 `font-mono`。现有 `PanelCard.jsx` 中将中文 eyebrow 套用 mono 的做法，应在对应迁移阶段移除。

### 5.2 字号层级

| 层级 | 字号 | 约束 |
| --- | ---: | --- |
| meta | 12px | 仅纯英文、数字、符号，可用 mono |
| caption | 13px | 中文辅助文字的最小字号 |
| body | 15px | 普通中文 UI 正文 |
| prose | 17px | 小说正文主阅读字号 |

禁止中文使用 `text-xs`。迁移时遇到现有中文 `text-[11px]`、`text-[12px]`，应按含义提升到 caption 或 body，不做机械全局替换。

## 6. Tailwind 语义 token 方案

`frontend-react/src/index.css` 继续作为唯一 Tailwind 入口。可新增 `frontend-react/src/styles/theme.css` 并由 `index.css` 引入，但 `theme.css` 不得重复写 `@import "tailwindcss"`。

第一阶段建立以下基础语义变量：

| token | 含义 | 亮色基准 |
| --- | --- | --- |
| `--background` | 页面/工作台底色 | `#fafaf9` |
| `--foreground` | 主文字 | stone 深色 |
| `--primary` | 主要操作与焦点 | `#ea580c` |
| `--border` | 分隔线与控件边界 | stone 暖灰 |
| `--muted` | 历史遗留次级文字色 token，Phase 1 暂不改含义 | 继承旧主题 |
| `--muted-bg` | 弱背景 / 次级表面 | stone 浅灰 |
| `--muted-foreground` | 新语义体系里的弱文字色 | stone 中灰 |
| `--accent` | hover、选中、强调背景 | orange 浅色 |
| `--surface` | 面板/栏位表面 | 暖白 |

暗色模式只改变这些语义变量的值，`--primary` 使用 `#f97316`。组件只消费语义 token，不根据 `paper / cool / deep / signal` 自行分支。

Phase 1 兼容说明：

- 当前仓库里的 `--muted` 已被旧页面大量用于次级文字色，不能在本阶段直接改成弱背景。
- 因此 Phase 1 新增 `--muted-bg` 承接弱背景语义，新增 `--muted-foreground` 承接新体系的弱文字语义。
- Tailwind 里的 `bg-muted` 先映射到 `var(--muted-bg)`，`text-muted-foreground` 映射到 `var(--muted-foreground)`。
- 旧代码中的 `color: var(--muted)` 本阶段不改；待旧组件迁移完成后，再在最终清理阶段统一收敛 `--muted`。

迁移期保留 `--brand / --line / --panel / --text` 等旧变量，并补齐新语义 token，先让旧页面和新工作台样式并存。Phase 7 确认所有引用清零后再删除兼容层。

正文字体可额外使用 `--font-prose`，由 ThemePopover 切换；UI 字体和 mono 字体保持固定。建议在 Tailwind 配置中只暴露语义颜色、字体和明确需要复用的字号，不复制整套旧 recipe。

## 7. StyleManager 降级方案

新增 `frontend-react/src/components/theme/ThemePopover.jsx`，将主题入口放进顶栏；本轮实际优先挂接 `GlobalBar.jsx`，因为它已经是工作台自己的顶栏，不需要为了放主题控件去改 `App.jsx` 主体逻辑。若后续工作台全屏模式需要其他入口，可复用同一组件，但不得复制状态逻辑。

Popover 只保留：

1. 明暗：light / dark。
2. 暖橙深浅：控制 `--primary` 与对应 accent 强度，选项数量保持少量且差异可见。
3. 正文字体：只影响小说正文和创作长文本，不影响按钮与中文 UI。

Phase 2 先将 `/style-manager` 重定向到 `/workbench`，并删除主导航入口，但暂不物理删除 `StyleManagerPage.jsx`。`/visual-sample` 当前也重定向至 `/style-manager`，Phase 2 必须同步改为 `/workbench` 或删除该旧跳转，避免重定向链。`verify:style-manager` 脚本如当前回合未授权修改 `package.json`，则保留到后续清理回合再移除，并在文档中明确这是文件范围约束，不是功能回退。

主题设置继续真正保存到浏览器存储，并在刷新后恢复（运行时主题持久化）；这不涉及后端或数据库。旧存储迁移仅在兼容期保留，最终是否清理以 Phase 7 前的实际使用情况为准。

## 8. shadcn/ui 接入原则

采用 shadcn/ui 的“源码复制到项目”模式，不安装完整组件库。基础组件放在 `frontend-react/src/components/ui/`：

- `button.jsx`
- `popover.jsx`
- `resizable.jsx`
- `separator.jsx`
- `tabs.jsx`
- `sidebar.jsx`

允许按实际组件需要安装 Radix Popover、Radix Tabs、`react-resizable-panels`、`clsx`、`tailwind-merge` 等小型基础依赖。每个依赖必须有当前 Phase 的直接使用者；不预装未来可能使用的包。

禁止引入 Ant Design、MUI、Element Plus 等大型 UI 组件库。基础组件必须消费第 6 节的语义 token，不复制 shadcn 默认冷灰色板，不引入新的主题系统，也不在 `components/ui` 中放业务状态。

## 9. 三栏工作台结构

目标结构：

```text
WorkbenchStage
└─ WorkbenchShell
   ├─ WorkbenchNavigator（左栏）
   │  ├─ 章节树
   │  ├─ 剧情线
   │  ├─ 角色
   │  └─ 伏笔
   ├─ WorkbenchMain（中栏，默认最大）
   │  └─ Tabs：章节任务 / 细纲 / 正文 / 反馈 / 校改
   └─ WorkbenchInspector（右栏）
      ├─ 章节反馈
      ├─ 角色执行
      ├─ 上下文
      └─ 下一章准备材料
```

职责边界：

- `WorkbenchShell.jsx`：只负责三栏尺寸、拖拽、折叠和全屏布局状态。
- `WorkbenchNavigator.jsx`：展示导航入口和选择状态，不自行请求或保存数据。
- `WorkbenchMain.jsx`：承载主 Tabs 和正文区域，继续接收现有业务 props。
- `WorkbenchInspector.jsx`：展示反馈与上下文，不改变其数据来源。
- `WorkbenchStage.jsx`：把现有 `chapterConfigProps`、`contentWorkspaceProps` 交给新壳，迁移期维持现有上层契约。

桌面端启用三栏拖拽；窄屏使用折叠/抽屉式降级，不强行维持三栏。中栏设置合理最小宽度并优先获得剩余空间。正文全屏只隐藏左右栏和非必要工具，不卸载正文状态，不触发生成或保存。

## 10. PanelCard 到 WorkbenchSection 的迁移方案

新增 `WorkbenchSection.jsx`，职责限定为分区标题、可选 meta、左边线、分隔线和内容间距。它不是换名字后的 Card：默认无阴影、无大圆角、无封闭式四边边框。

建议接口保持简单：`code`、`title`、`description`、`actions`、`children`、`className`。`code` 只接收英文/数字代号，并通过 `MetaCode.jsx` 输出 mono 文本；中文标题使用 sans 或 serif，字号不得低于 13px。

迁移顺序：

1. Phase 4 先用新壳承载旧 `ChapterConfigPanel` 和 `ContentWorkspace`，不改内部卡片。
2. Phase 5 只迁移 `ContentWorkspace.jsx`，重点移除正文区的 `PanelCard`、圆角结果容器和嵌套表面。
3. Phase 6 再迁移 `ChapterConfigPanel.jsx`，按业务语义拆分为 `TASK / STORYLINE / MOOD / CAST / OUTPUT`。
4. Phase 7 用全仓引用检查确认 `PanelCard`、`insetSurfaceClass` 无使用者后再删除。

迁移只改变展示容器。生成正文只是后端把结果返回给网页；是否保存章节仍取决于现有前端后续保存动作。不得因去卡片化而合并、删除或改写生成与保存步骤。

## 11. Phase 1 到 Phase 7 的迁移计划

### Phase 1：新增 Tailwind 语义 token + 保留旧 token 兼容层

建立新语义变量和字体规则，保留旧主题大表、旧组件和全部业务界面，先让新旧样式可以并存。由于 `--muted` 当前仍承担历史文字色职责，Phase 1 使用 `--muted-bg` 承接弱背景语义，不对旧 `var(--muted)` 用法做全局替换。

### Phase 2：StyleManager 降级为 ThemePopover

在顶栏提供三个真实主题控制，将旧独立页面路由重定向到工作台，移除主导航入口；页面文件暂时保留。若当前回合文件范围不包含 `package.json`，旧验证脚本入口可延后到后续清理回合移除。

### Phase 3：接入 shadcn/ui 基础组件

新增 `components/ui`，按需接入 Button、Popover、Resizable、Separator、Tabs、Sidebar 及其最小依赖，为工作台壳提供稳定基础。

本轮实际策略：只新增 `components/ui` 基础组件与 `src/lib/utils.js`，不迁移真实工作台；允许的小依赖仅限 `clsx`、`tailwind-merge`、`@radix-ui/react-slot`、`@radix-ui/react-separator`、`@radix-ui/react-tabs`、`@radix-ui/react-popover`、`react-resizable-panels`；不引入 Card 组件，不使用 shadcn CLI，只手写源码组件。

### Phase 4：建立三栏工作台壳

新增 Shell、Navigator、Main、Inspector，并修改 `WorkbenchStage.jsx`。先原样嵌入旧业务组件，验证布局切换不影响业务行为。

### Phase 5：ContentWorkspace 去卡片化

新增 WorkbenchSection、MetaCode，可选 Typography。只迁移生成前/生成后内容与正文阅读区域，建立 `alipro-editor-prose`。

### Phase 6：ChapterConfigPanel 去卡片化

按 TASK、STORYLINE、MOOD、CAST、OUTPUT 重组视觉分区，复用 WorkbenchSection，但保持字段与保存行为不变。

### Phase 7：最终清理

删除无引用的旧页面、PanelCard、旧验证脚本和旧主题体系；新增 UI 样式契约检查脚本，并接入 `check:ui-style`。

## 13. 每阶段禁止事项

### Phase 1

- 禁止删除 `PanelCard.jsx`、`StyleManagerPage.jsx` 或旧 `styleTheme.js` 大表。
- 禁止修改工作台业务组件。
- 禁止删除旧 token；只能增加新 token 和兼容映射。
- 禁止全局替换旧页面里的 `var(--muted)`；Phase 1 只新增 `--muted-bg / --muted-foreground`。
- 禁止修改后端、数据库、AI 生成接口。

### Phase 2

- 禁止物理删除 `StyleManagerPage.jsx`。
- 禁止保留看似可调但差异不可见的控制项。
- 禁止改变主题以外的工作台业务状态。
- 禁止把主题偏好写入业务数据库。

### Phase 3

- 禁止引入 Ant Design、MUI、Element Plus 等大型 UI 库。
- 禁止一次性复制未使用的 shadcn/ui 组件。
- 禁止在基础组件内加入章节、剧情线、生成等业务逻辑。
- 禁止建立第二套颜色 token。

### Phase 4

- 禁止重写 `ChapterConfigPanel`、`ContentWorkspace` 的业务逻辑。
- 禁止删除 `PanelCard.jsx`。
- 禁止改变 props 契约、接口调用和保存顺序。
- 禁止修改后端。

### Phase 5

- 禁止顺带改 `ChapterConfigPanel.jsx`。
- 禁止将生成成功描述为保存成功。
- 禁止改生成接口、保存接口或正文数据结构。
- 禁止中文正文小于 17px，禁止中文元信息使用 mono。

### Phase 6

- 禁止改变字段含义、默认值、校验条件或保存接口。
- 禁止把多个现有保存动作擅自合并为单一接口能力。
- 禁止修改后端、数据库和 AI 生成接口。
- 禁止为视觉分区复制业务状态。

### Phase 7

- 禁止在仍有引用时删除旧 token、组件或迁移函数。
- 禁止仅凭构建通过就认定完整验收通过。
- 禁止清理与本次工作台重构无关的历史代码。
- 禁止全项目格式化或无关重构。

## 14. 每阶段验收标准

## 16. 最终验收标准

6. `/style-manager`、主导航入口、旧页面、旧脚本、旧 recipe、旧 token 和 PanelCard 均已按无引用原则清理。
