# 章节细纲单一最新稿方案

## 目标

把“章节细纲”收口成前端唯一可见、唯一可编辑、唯一参与正文生成的当前稿。

用户在前端不再区分：

- 系统生成稿
- 手动编辑稿
- 结构化任务表草稿

前端只显示一份内容：

- `章节细纲`

这份内容始终代表“当前最新可用版本”。

## 前端规则

### 1. 显示规则

- 工作台只显示一份章节细纲文本。
- 章节卡片、生成摘要、正文生成入口，都读取这一份最新细纲。
- 不再把旧的结构化六字段作为主展示内容。
- 如果当前只有旧结构字段，没有正式细纲文本，前端显示“尚未生成正式细纲”，不自动把结构字段拼成一段假细纲给用户看。

### 2. 覆盖规则

- 用户手动保存章节细纲：覆盖当前版本。
- 用户点击系统生成章节细纲：覆盖当前版本。
- 前端不保留“双稿并存”状态。

### 3. 来源规则

前端只做简化展示：

- `手动编辑`
- `系统生成`

来源只用于提示当前版本从哪里来，不用于前端分叉显示。

## 后端规则

### 1. 存储主字段

章节细纲正式主字段：

- `chapter_plans.outline_text`

它是当前章节细纲的正式文本版本。

### 2. 来源记录

后端继续保留来源：

- `manual`
- `ai`
- `imported`

这样后续如果要做统计、追溯或审计，不需要再改表结构。

### 3. 兼容层处理

旧结构化字段暂时不删，但退到兼容层：

- `chapter_mission`
- `emotion_target`
- `scene_outline`
- `ending_hook`
- `structured_content.chapter_outline_structure`

这些字段不再作为前端主入口，也不允许反向覆盖 `outline_text`。

## 正文生成规则

### 输入

正文生成优先读取：

1. `chapter_plans.outline_text`
2. 如果没有细纲文本，再退回旧兼容结构
3. 如果连兼容结构都没有，再看是否至少挂载了剧情线

### 解释

也就是说：

- 当前有细纲，就按细纲生成
- 当前没细纲，但有剧情线，可走“剧情线兜底生成”
- 当前既没细纲也没剧情线，不允许直接生成

注意：

- 这里的“退回旧兼容结构”只发生在生成链路内部。
- 前端展示层不显示这段拼接结果，避免把结构化任务误认为正式章节细纲。

## 细纲容量约束（2026-08-07 新增）

### 背景

章节细纲偶尔把完整因果闭环（触发→调查→破解→抓捕→善后）全部塞进一章，正文在目标字数内写不完，而正文审计又要求细纲节点全部落地，导致正文超字数或被判 needs_review。

### 规则

1. 一章正文目标约 3000 有效字，通常只能完成 2-4 个关键事件节点。
2. 关键事件节点 = 有开始、有过程、有明确结果的完整事件（“破解密信”“当场抓获”各算一个节点）；背景交代、环境铺垫、人物状态描写不算节点。
3. 细纲生成提示词强制：只保留本章 2-3 个关键事件节点（最多 4 个），细纲正文 220-400 字，放不下的拆到下一章，并写明“本章停点 + 下章承接”。
4. 细纲生成后跑密度审校（`auditOutlineEventDensity`）：超过 4 个节点或超过 400 字判 `overloaded`，自动重写最多 2 次，重写提示附“必须移除的节点”清单；结尾“本章停点/下一章承接”中的未来事件不计入节点数。

### 正文审计口径

正文审计 `outline_coverage_audit` 增加 `carryover_beats`：

- 下一章承接节点放入 `carryover_beats`，本章未完成不算缺失。
- `missing_beats` 只放“本章应完成但正文未落实”的节点。
- 只有 `missing_beats` 非空时才产生 outline coverage 风险；自动修稿不再强行补写下章承接节点。

### 保存兼容修复（2026-08-07）

`ChapterPlanService.upsert` 原为全量覆盖：调用方只传部分字段时，会把 `chapter_name`、`summary`、`chapter_mission`、`structured_content`（含 `storyline_context`）清空。已改为 merge 语义：

- 已有章节规划时，请求中未提供的字段沿用当前行的值；
- `structured_content` 未提供时保留旧值，只更新调用方传入的部分；
- 显式清空字段仍可通过传入空字符串/空数组实现，但一般清空操作走删除接口，不使用 upsert。

### 角色空降校验（2026-08-07 新增）

细纲生成时新增角色连续性审校（`auditOutlineRoleContinuity`），防止“角色库里有设定但前文从未出场”的角色空降承担关键功能（救人、点破真相、提供关键情报等）：

- 生成前收集前文（1 到 N-1 章）已出场角色：前文正文中出现的角色库角色 + 前文章节规划挂接的出场角色/角色执行条目；
- 细纲生成后由审校模型对照前文名单判断：不在名单且未写明自然引入方式的角色若承担关键功能，判 `needs_revision`，自动重写一次（最多 2 轮），重写提示给出处理建议；
- 正文审计同步增加 airdrop 兜底维度：正文出现前文零出场的角色承担关键功能时写入 `airdrop_items` 和 risks；
- 细纲生成提示词（`buildOutlinePrompt`）增加角色出场连续性约束，从源头限制空降。

## 本次实现边界

这次先完成：

1. 前端只保留一份章节细纲
2. 系统生成和手动保存都覆盖当前稿
3. 正文生成优先吃最新细纲
4. 后端保留来源信息

这次暂不完成：

1. 把章节细纲文本自动反解回结构化字段
2. 从章节细纲里自动抽“目标 / 场景 / 冲突 / 情绪落点 / 钩子”
3. 基于细纲文本自动重建章节任务表

## 后续可继续做的增强

### 1. 细纲抽取器

增加一个“细纲转结构化信息”的模型步骤。

作用：

- 用户只写叙事型细纲
- 系统自动提炼出目标、场景、冲突、角色变化、情绪落点、钩子
- 这些结构化字段只给后端和生成链路用，不增加前端填写负担

### 2. 版本历史

如果以后要补版本回看，建议做：

- 当前最新稿
- 最近一次系统生成稿
- 最近一次手动保存稿

但默认只展示“当前最新稿”，历史版本收进二级入口，不回到双稿并排。
