# 本地 IDE 前端规划（参考「星炉」纸感配色）

> 依据：B 站视频《亿万字聊天完成：AI写作彻底换代了》（BV1L23z6eEak）中「星炉」的实测配色与布局；项目现状为 React 18 + Vite 5 + Tailwind 4 + react-resizable-panels。

> 落地现状（2026-08）：导航已从顶部切换到左侧 IDE 侧边栏（`AppLayout.jsx` + `ide-shell.css`），
> 按「创作 / 多媒体 / 探索 / 系统」分组，未来页面只需在导航数组加项并注册路由；
> 有声书页面已上线，视频工坊 / 灵感探索为占位入口。桌面壳新增显示比例自适应与缩放持久化。
> 创作台新增 `workbench-paper.css` 纸感语言层：面板头 / 卡片（16px 圆角 + 柔和阴影）/
> 框中框 / 控件与按钮样式与有声书页对齐，不改布局骨架。

## 一、设计目标

1. 把现有工作台从"冷蓝科技风"转向"纸感暖白风"，主色板参考星炉实测值。
2. 布局 IDE 化：作品树（左） + 正文编辑（中） + 上下文面板（右） + 底部状态栏，Win / Mac 一致。
3. 复用现有组件与业务逻辑，不做无关重构；跨平台优先零新增依赖。

## 三、布局架构（IDE 化）

```text
┌─────────────────────────────────────────────────────────────┐
│ 顶部导航（保留 AppLayout：资料库 / 创作台 / 更新日志 + 品牌）    │
├───────────────┬──────────────────────────────┬──────────────┤
│ 左栏 240-300px│ 中栏（弹性）                  │ 右栏 280-340px│
│ 作品树        │ 上下文工具栏（GlobalBar）      │ 上下文面板    │
│ · 书 → 卷 → 章│ 正文纸面（prose paper）        │ · 章节设定     │
│ · 剧情线       │ · AI 生成 / 修订 / 审阅区      │ · 角色         │
│ · 角色 / 设置  │ · 生成预览                    │ · 剧情线       │
│ 顶部标签切换   │                              │ · 生成参数     │
├───────────────┴──────────────────────────────┴──────────────┤
│ 底部状态栏（新增）：生成状态 / 字数 / 模型 / API 用量 / 保存状态 │
└─────────────────────────────────────────────────────────────┘
```

设计要点（来自星炉的启示）：

1. **底部状态栏**：星炉把"剩余创作点"放在顶部常驻；本项目的等价物是字数、API 用量、生成状态，放底部状态栏最符合 IDE 习惯，不挤占导航。
2. **左栏标签页化**：作品树 / 剧情线 / 角色 / 设置 用标签切换，避免当前侧栏长列表堆叠（现状 `.workbench-sidebar-section` 可折叠，升级为 tabs 更 IDE）。
3. **右栏固定上下文**：现状 Drawer（BookSetting / Character / Storyline / Volume）是浮层；IDE 化后作为固定右栏标签页，点击章节目录即联动展示当前章上下文。
4. **中栏纸面感**：正文区用 `--surface-raised` 白底 + 浅边框，配合 serif 字体，接近"纸稿"而非"控制台"。
5. **过程可视化（星炉亮点）**：生成时在生成预览区展示步骤链（规划大纲 → 检索设定 → 写作 → 校验），让 AI 行为透明。

## 五、跨平台技术选型（Win + Mac）

**结论：第一阶段保持纯 Web（Vite），零新增依赖；桌面壳作为二期可选。**

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| 纯 Web（现状） | 零依赖；Win/Mac 浏览器一致；`npm run dev` / `npm run build` + 本地静态服务即可 | 无独立窗口、无系统托盘 | 第一阶段 |
| Tauri 2（二期） | 包小（10MB 级）；Win WebView2 + Mac WKWebView；前端代码不变 | 需要 Rust 工具链 | 需要"真桌面感"时选它 |
| Electron（二期） | 生态最成熟；复用 Node | 包大（100MB+）、内存高 | 除非强依赖 Node 桌面能力 |

前端业务层已全部走 HTTP（`workbenchApi.js`），桌面壳只做窗口容器，业务代码零改动。

## 六、落地步骤（最小修改）

1. **阶段 1 换色（半天内）**：替换 `styles/theme.css` 的 token 为 2.1 表；排查 `cinematic-theme.css`、`product-ui.css`、`workbench-layout.css`、`styles.css` 中的变量覆盖与硬编码 hex（`rg --glob "*.css" "#[0-9A-Fa-f]{6}" src`），统一到 token。
2. **阶段 2 布局**：新增底部 `StatusBar`；左栏包一层 tabs 容器；抽屉改造为右栏固定面板（组件内部逻辑不动）。
3. **阶段 3 打磨**：圆角 8-10px、浅阴影、留白节奏、焦点态（`--border-strong`）、正文 serif 行高 1.8。
4. **验证**：`npm run build` + 浏览器逐页检查（资料库 / 创作台 / 提示词 / 剧情线 / 更新日志）；确认无硬编码冷蓝色残留。

## 七、风险与注意

- 多 CSS 文件存在变量覆盖链（accent 被 `cinema-gold` 覆盖），换色必须全局清理，否则出现"局部还蓝着"。
- 当前主题可切换（`ThemePopover`）：建议新增"纸感"主题选项，保留现有冷色/电影主题为备选，避免破坏已有用户偏好。
- 配色改动是全局性的，建议先在 Git 分支上做，便于回滚。
