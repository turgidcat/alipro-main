# 小说生成逻辑重构方案

> 创建日期：2026-05-30
> 目标：遵循「全书大纲 → 分卷大纲 → 章节细纲 → 正文生成」的自然创作规律，重构生成流水线

---

## 一、现状问题诊断

### 1.1 续写缺乏剧情可靠性

**现象**：`/api/continue` 续写时只取上文最后 500 字作为上下文，没有任何剧情规划依据。

```
当前续写流：
  用户点"续写" → 取上文.slice(-500) → 直接丢给 AI → 出正文
```

**问题**：
- AI 只能看到最近 500 字，不知道整章乃至整卷的剧情走向
- 不知道本章核心冲突是什么、应该推进到什么程度
- 容易跑偏：角色行为不一致、情节跳跃、节奏失控
- 本质上是在"盲写"，没有任何规划

### 1.2 大纲与生成脱节

当前系统存在**两套大纲存储体系**，但都没有被正文生成环节有效利用：

| 存储位置 | 内容 | 与生成的关系 |
|---|---|---|
| `novel_outlines` 表（三级大纲） | 全书/分卷/章节大纲 | **无自动关联**，前端独立管理 |
| `chapters.outline` 字段 | 章节写作大纲 | 用户手动填入文本框后传给 AI |

**问题**：
- `novel_outlines` 的章节大纲（type=chapter）从未被 `buildCreativePrompt` 读取
- 正文生成时用的 outline 来自前端文本框，靠用户手动复制粘贴
- 全书大纲和分卷大纲完全没进入生成 prompt，AI 不知道当前章节在全书中的位置

### 1.3 "先写后补大纲"的倒置流程

```js
// 当前 continueWriting() 逻辑
continueWriting() → AI生成正文 → 保存章节 → generateOutlineForNewChapter() 补大纲
```

续写完成后才调用 AI 为下一章生成大纲，这是**因果倒置**——应该先有规划，再动笔。

### 1.4 章节大纲粒度不足

当前章节大纲是 150-250 字的 5 要点框架：

```
1. 核心冲突（一句话）
2. 剧情走向（关键节点，箭头连接）
3. 关键场景（2-3个）
4. 情绪基调（1-2个词）
5. 悬念设置（可选）
```

这对于长篇创作来说太粗糙。缺少：
- 具体的场景序列（什么时候、什么地方、发生什么）
- 角色行为动机（谁做了什么、为什么）
- 对话要点（本章需要通过对话推进哪些关键信息）
- 情绪曲线（紧张→舒缓→紧张的节奏控制）
- 与上下章的衔接点（承接什么钩子、埋什么钩子）

### 1.5 全书大纲没有自动拆解

`handleFullOutlineGeneration` 生成的是一段 600-1000 字的文本，包含分卷规划但未结构化。用户需要手动将这段文本拆分为分卷大纲和章节规划，与后续生成流程脱节。

## 二、重构目标

| 目标 | 说明 |
|---|---|
| **层级清晰** | 全书大纲 → 分卷大纲 → 章节细纲 → 正文生成，四级规划体系 |
| **强关联** | 每一层生成的 prompt 都注入上层规划的上下文，AI 始终知道"我在写哪一部分" |
| **先规划后动笔** | 正文生成前细纲必须存在；续写 = 进入下一章的正文生成 |
| **细纲去框化** | 章节细纲从"5要点框架"升级为"场景序列"，提供足够细节支撑正文创作 |
| **可审核可修改** | 每一层产出都允许用户审核和手动编辑，确认后再进入下一层 |

## 三、新创作层级

```
┌─────────────────────────────────────────────────────┐
│                   I. 全书大纲                         │
│  • 故事主线（3-5句）                                  │
│  • 分卷规划（每卷名称+核心事件+预估章数）               │
│  • 主要矛盾线（2-3条，起始→发展→高潮→解决）             │
│  • 世界观要点                                          │
│  • 角色成长弧线总览（主角/重要配角的变化轨迹）           │
└──────────────┬──────────────────────────────────────┘
               │ 拆分
               ▼
┌─────────────────────────────────────────────────────┐
│                II. 分卷大纲（N卷）                     │
│  • 本卷核心矛盾                                        │
│  • 角色本卷成长目标                                     │
│  • 关键事件链（按章节排列的事件节点）                    │
│  • 章节规划（第1章做什么、第2章做什么...）               │
│  • 本卷情绪总基调                                       │
└──────────────┬──────────────────────────────────────┘
               │ 拆分
               ▼
┌─────────────────────────────────────────────────────┐
│              III. 章节细纲（M章/卷）                    │
│  • 本章核心目标（本章要完成什么剧情推进）                │
│  • 承上：承接上一章的结尾钩子/悬念                       │
│  • 场景序列（3-5个场景，每个含：）                      │
│     - 地点/时间/氛围                                   │
│     - 出场角色及其行为目标                              │
│     - 场景核心事件                                      │
│     - 场景产出（信息揭示/角色变化/关系变化）              │
│  • 情绪曲线标注（紧张↗缓和↘紧张↗...）                   │
│  • 关键对话要点（哪些信息必须通过对话推进）               │
│  • 启下：为下一章埋下的钩子/悬念                         │
└──────────────┬──────────────────────────────────────┘
               │ 基于细纲
               ▼
┌─────────────────────────────────────────────────────┐
│               IV. 正文生成                             │
│  Prompt 注入：                                        │
│  • 本章完整细纲                                        │
│  • 上一章细纲摘要（了解来龙去脉）                        │
│  • 上一章正文最后 500 字（风格衔接）                     │
│  • 当前分卷核心矛盾（保持大方向）                        │
│  • 全书世界观约束                                       │
│  • 角色设定                                             │
└─────────────────────────────────────────────────────┘
```

## 四、各阶段详细设计

### 4.1 阶段一：全书大纲生成

**触发**：用户创建新书后，点击"生成全书大纲"

**输入**：
- 书籍类型/子类型/平台
- 书名
- 角色设定
- 用户可选补充：核心创意/想写的主题/大致篇幅（总字数）

**输出**：结构化全书大纲（JSON 格式）

```json
{
  "mainPlot": "故事主线 3-5句",
  "volumes": [
    {
      "number": 1,
      "title": "第一卷名称",
      "theme": "本卷主题",
      "coreEvents": ["事件1", "事件2", "事件3"],
      "estimatedChapters": 12
    }
  ],
  "conflictLines": [
    {
      "name": "矛盾线名称",
      "stages": ["起始", "发展", "激化", "高潮", "解决"]
    }
  ],
  "worldbuilding": ["世界观要点1", "要点2"],
  "characterArcs": {
    "主角": "从...成长为...",
    "重要配角": "从...变化为..."
  }
}
```

**用户操作**：
- 审核全书大纲内容
- 可逐项修改（主线/分卷/矛盾线等）
- 确认后系统自动创建所有分卷记录（`novel_outlines` type=volume）

**AI 调用参数**：
- 模型：deepseek-chat
- temperature：0.85（需要创意但要有结构性）
- 要求返回 JSON，严格按指定 schema

### 4.2 阶段二：分卷大纲生成

**触发**：用户选择某一卷，点击"生成分卷大纲"

**输入**：
- 全书大纲中该卷的规划
- 角色设定
- 前一卷的分卷大纲（非首卷时，了解衔接）
- 全书整体矛盾线

**输出**：结构化分卷大纲

```json
{
  "volumeNumber": 1,
  "volumeTitle": "分卷标题",
  "coreConflict": "本卷核心矛盾描述",
  "characterGrowth": {
    "主角": "本卷中的成长目标",
    "配角": "本卷中的变化"
  },
  "keyEvents": [
    {
      "chapterApprox": 1,
      "event": "关键事件描述",
      "purpose": "这个事件推动的剧情目标"
    }
  ],
  "emotionTone": "本卷整体情绪基调",
  "chapterPlan": [
    {
      "chapterNumber": 1,
      "titleHint": "章节主题提示",
      "goal": "本章要完成什么"
    }
  ],
  "totalChapters": 12
}
```

**用户操作**：
- 审核分卷大纲
- 调整/增删关键事件
- 调整章节数量和规划
- 确认后系统创建该卷下所有空章节记录（chapters 表）

**AI 调用参数**：
- 模型：deepseek-chat
- temperature：0.8
- 要求返回 JSON

### 4.3 阶段三：章节细纲生成（★ 核心新增）

这是本次重构最关键的环节。章节细纲取代原来的"5要点框架式大纲"，提供场景级别的规划。

**触发**：
- 方式一：在分卷大纲确认后，批量生成该卷所有章节的细纲
- 方式二：逐章手动触发（更精细控制）

**输入（生成细纲时注入的上下文）**：
- 全书大纲摘要（100-200字梗概）
- 所属分卷大纲（完整内容）
- 本章在分卷中的位置和规划目标
- 上一章的细纲（"启下"字段，用于承上）
- 角色设定
- 全书世界观约束

**输出**：章节细纲（500-800字）

- 推荐串行方案以保证剧情连贯性

**用户操作**：
- 逐章审核细纲（章节卡片列表展示）
- 可修改任何字段（场景增删/调整/情绪标注）
- 确认单章或批量确认
- 确认后标记 `status: confirmed`，允许进入正文生成

**AI 调用参数**：
- 模型：deepseek-chat
- temperature：0.75
- maxTokens：2000
- 要求返回 JSON

### 4.4 阶段四：正文生成（重构）

**触发**：用户选择某一章（细纲已确认），点击"生成正文"

**输入（重构后的 prompt 注入）**：

| 注入内容 | 来源 | 用途 |
|---|---|---|
| 本章完整细纲 | `novel_outlines` type=chapter | 场景序列、对话要点、情绪参考 |
| 上一章细纲摘要 | 上一章的 chapterGoal + leadToNext | 知道从哪里接续 |
| 上一章正文最后 500 字 | `chapters.content` | 风格衔接、细节连贯 |
| 当前分卷摘要 | `novel_outlines` type=volume | 知道本章在当前卷中的位置和目标 |
| 全书大纲摘要 | `novel_outlines` type=book | 世界观约束、总体方向 |
| 角色设定 | `novel_characters` | 角色一致性 |
| 创作参数 | 前端设置 | 爽点/情绪/口语化/对话占比等 |

**重写 buildCreativePrompt**：

```
你是一位资深{platform}网文作家，正在创作{genre}({subgenre})类小说《{bookTitle}》。

【全书概要】{bookOutlineSummary}

【当前分卷·第{volumeNumber}卷《{volumeTitle}》】
本卷核心矛盾：{volumeCoreConflict}
本卷中本章的位置：第{chapterNumber}章/共{totalChapters}章

【承接上文】
上一章结局：{previousChapterGoal} → {previousChapterHook}
上文最后一段：{last500Chars}

【本章细纲】
- 核心目标：{chapterGoal}
- 场景序列：
  * 场景1（{location}, {time}, {atmosphere}）：{action} → {output}
  * 场景2（{location}, {time}, {atmosphere}）：{action} → {output}
  * ...
- 情绪曲线：{emotionCurve}
- 关键对话要点：{dialoguePoints}
- 本章结尾钩子：{leadToNext.hook}

【角色状态】
{characterStates}

【创作要求】
- 爽点标签：{shuangTags}
- 情绪强度：{emotionIntensity}%
- 口语化程度：{colloquialLevel}%
- 对话占比：约{dialogueRatio}%
- 字数：{wordCount}字
- 其他开关：{flags}

请按照细纲的场景序列逐场景创作。每个场景之间用空行分隔。
直接输出正文内容，不要输出章节序号或标题。
```

**关键变化**：
- 不再只是"大纲"一个模糊字段，而是注入完整的场景级细纲
- AI 知道上一章发生了什么、本章在哪里、下一章要埋什么钩子
- 上下文远超 500 字：细纲中的前后衔接信息足够 AI 保持连贯

### 4.5 续写逻辑重构

**核心思路**：**取消独立的"续写"模式**。续写本质上就是"进入下一章的正文生成"。

**新续写流**：

```
用户点"续写/下一章"
  │
  ├─ 检查：下一章的细纲是否存在且已确认？
  │     │
  │     ├─ 是 → 直接进入正文生成（阶段四）
  │     │
  │     └─ 否 → 提示：
  │           "第X章还没有细纲，是否现在生成？"
  │              │
  │              ├─ 是 → AI生成细纲 → 用户审核 → 正文生成
  │              └─ 否 → 中止，用户可手动填写
  │
  └─ 正文生成（注入完整上下文）
```

**与旧续写的本质区别**：

| 对比维度 | 旧续写 | 新续写 |
|---|---|---|
| 规划依据 | 上文最后500字 | 完整章节细纲 + 分卷大纲 + 全书大纲 |
| 剧情控制 | AI 自由发挥，容易偏 | 按细纲场景序列创作，方向可控 |
| 产出顺序 | 先出正文 → 后补大纲 | 先审细纲 → 再出正文 |
| 连贯性 | 差，常出现前后矛盾 | 强，细纲明确标注承上启下 |
| 用户体验 | 一键续写，结果不可控 | 可预览本章要写什么，再决定要不要生成 |

## 五、API 设计

### 5.1 大纲相关

```
# 全书大纲
POST   /api/outlines/:bookId/book/generate    # AI生成全书大纲
GET    /api/outlines/:bookId/book              # 获取全书大纲
PUT    /api/outlines/:bookId/book              # 更新全书大纲（用户编辑后保存）

# 分卷大纲
POST   /api/outlines/:bookId/volume/:volNum/generate  # AI生成分卷大纲
GET    /api/outlines/:bookId/volumes                   # 获取所有分卷大纲
PUT    /api/outlines/:bookId/volume/:volNum            # 更新分卷大纲
DELETE /api/outlines/:bookId/volume/:volNum            # 删除分卷
POST   /api/outlines/:bookId/volumes/create            # 从全书大纲创建所有分卷记录

# 章节细纲
POST   /api/outlines/:bookId/chapter/:chNum/generate    # AI生成单章细纲
POST   /api/outlines/:bookId/volume/:volNum/generate-all # 批量生成该卷所有章节细纲
GET    /api/outlines/:bookId/chapters                    # 获取所有章节细纲
PUT    /api/outlines/:bookId/chapter/:chNum              # 更新章节细纲
GET    /api/outlines/:bookId/chapter/:chNum              # 获取单章细纲
```

### 5.2 生成相关

```
# 正文生成（重构）
POST   /api/generate              # 基于细纲生成正文（现有端点，逻辑重写）
POST   /api/generate/batch        # 批量生成多章正文

# 续写（改为基于细纲的章节切换）
POST   /api/chapters/:bookId/next # 检查下一章细纲状态，进入下一章流程

# 移除
[DELETE] /api/continue            # 移除旧的续写端点
```

### 5.3 辅助功能（保留）

```
POST   /api/polish                # 润色（保留，增加细纲上下文）
POST   /api/check-character       # 角色一致性检查（保留）
POST   /api/check-plot            # 剧情冲突检测（保留）
POST   /api/detect-foreshadowing  # 伏笔识别（保留）
```

### 6.1 novel_outlines 表扩展


## 十、关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 全书大纲格式 | JSON 结构化 | 便于程序解析和拆分为分卷/章节 |
| 细纲生成方式 | 串行（批量时逐章） | 每章细纲依赖上一章的启下字段，串行保证连贯性 |
| 正文生成上下文 | 本章细纲 + 上一章细纲摘要 + 上一章正文尾 + 分卷摘要 | 覆盖短中长期上下文，既有细节又有方向 |
| 细纲确认机制 | 用户必须确认后才能生成正文 | 避免 AI 在未确认的规划上自由发挥 |
| 旧大纲兼容 | 保留 chapters.outline 字段，作为降级方案 | 如果 novel_outlines 缺失，仍可用旧字段 |
| 旧续写端点 | 废弃，前端不再调用 | 避免用户混淆两种模式 |

## 十一、风险与注意事项

1. **细纲质量决定正文质量**：如果细纲 AI 生成质量差，正文也会受影响。需要提供手动编辑入口。
2. **批量生成成本**：一本 100 章的书，仅细纲就需要 100 次 API 调用，需考虑 token 消耗。
3. **用户创作自由度**：过于严格的细纲约束可能限制 AI 的发挥空间。应在 prompt 中设置"细纲为指导而非铁律"的提示。
4. **迭代修改循环**：用户可能在生成正文后想回头修改细纲，需要支持"基于修改后的细纲重新生成正文"。
5. **细纲 vs 正文的一致性检查**：生成的正文是否符合细纲规划？可能需要增加一致性校验环节。
